In Place of Caddyfile

Why Native Caddy JSON?

According to the official Caddy documentation, the Caddyfile is just an adapter. Under the hood:

Caddyfile Adapter

Great for human text editing, but static, requiring compilation and lacks dynamic programmatic API controls.

Native Caddy JSON

The true source of truth. Powers live zero-downtime reconfiguration over the Caddy Admin API.

The Catch: When you manage 10+ reverse proxies on a VPS, native Caddy JSON becomes deeply nested with apps.http.servers.srv0.routes.

The caddy-cli Bridge: You don't have to choose! Use native Caddy JSON for all its programmatic power, while caddy-cli gives you instant, crystal-clear visibility.

Official Caddy Reference & Internal Engine

How It Works & Official References

1. Host Matching ($..host[*]) Caddy Host Matcher Docs

Caddy encapsulates host declarations in route matchers. We use jsonpathly to extract hostnames without brittle manual loops.

2. Reverse Proxy Upstreams (dial) Caddy Dial Upstream Docs

Caddy defines backend targets using dial (e.g. localhost:8080). We extract and group these to instantly display occupied ports.

3. Subroutes & Path Handlers Caddy Subroute Docs

Subroutes group multiple handlers under one domain (e.g. WebSocket on /ws* and main app on *). Our engine recursively resolves and maps both.
