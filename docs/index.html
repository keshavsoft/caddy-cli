The Problem & The Solution

Why We Defined caddy-cli

Caddy is one of the most powerful modern web servers in existence: automatic TLS, HTTP/3, and a high-performance native JSON configuration engine. However, when managing a VPS running multiple microservices, Node.js backends, WebSocket handlers, and static sites, /etc/caddy/caddy.json rapidly grows into hundreds of lines of nested arrays:

apps → http → servers → srv0 → routes[0] → handle[0] → routes[1] → handle[0] → upstreams[0] → dial: "localhost:9011"

Whenever a developer SSH'es into a VPS or checks a machine, they always face three essential questions:

  • What subdomains are live right now?
  • Which local port / upstream does each domain forward to? (Is port 3001 free? Which service is on 9328?)
  • What does the specific routing block look like for a single domain?

Manually scrolling through 300 lines of JSON or writing fragile jq expressions over SSH is slow and prone to errors. caddy-cli solves this completely: run npx caddy-cli anywhere and instantly get clean, structured observability in milliseconds.

Engineering & Design Architecture

How We Thought Through the Architecture

1. The JSONPath Engine (jsonpathly)

Instead of hardcoding brittle recursive loops that break whenever Caddy adds a new wrapper or nesting level, we leverage jsonpathly with the universal JSONPath expression:

export const HOST_EXPRESSION = "$..host[*]";

This immediately extracts every single host declaration across all HTTP servers, subroutes, and handlers, along with their exact structural JSON paths in the configuration tree.

2. Modular Version Evolution (src/v1, src/v2, src/v3)

Inspired by the KeshavSoft versioned architecture (seen in monaco-ide and spec-repo), each major milestone lives in its own dedicated version folder. The root entry points (src/index.js and src/cli.js) cleanly re-export the active flagship while maintaining backwards compatibility:

caddy-cli/
├── bin/index.js
├── src/
│ ├── v1/ # Hostname & JSONPath querying
│ ├── v2/ # Upstream ports, reverse proxy dials & domain drill-down
│ ├── cli.js # Re-exports active CLI
│ └── index.js # Re-exports active ESM API
└── package.json
